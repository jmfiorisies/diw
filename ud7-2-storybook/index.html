    7.2 · Desarrollo y Documentación Aislada con Storybook

    Criterios trabajados

    Criterio Cobertura
    RA4.a — Tecnologías de inclusión de contenido multimedia e interactivo ✅ Completa
    RA4.c — Herramientas gráficas para el desarrollo de contenido multimedia interactivo ✅ Completa
    RA4.d — Análisis del código generado por herramientas de desarrollo de contenido interactivo ✅ Completa
    RA3.d, e, f, g — Evaluación práctica (tratamiento de imagen, audio/vídeo, animaciones, import/export) ✅ Completa

    1. ¿Qué problema resuelve Storybook?

    Hasta ahora, para visualizar un componente (Button, Card) era necesario renderizar la página completa en la que estaba integrado. Storybook aísla cada componente en su propio entorno de desarrollo e inspección, independiente del resto de la aplicación.

    flowchart TD
    subgraph Tradicional ["Desarrollo Tradicional"]
        A["Sin Storybook<br/>Para probar un botón,<br/>se debe ejecutar la app completa"] --> P["Problema:<br/>Lento, dependencias pesadas,<br/>difícil de compartir"]
    end

    subgraph Componentes ["Entorno Aislado"]
        B["Con Storybook<br/>El componente vive en<br/>su propia 'story'"] --> S["Solución:<br/>Aislado, rápido, documentado<br/>y compartible vía URL"]
    end

    Storybook constituye la versión ejecutable en código de la guía de estilo documentada en la UD2 (Figma) y extendida en la UD5, dando continuidad práctica al criterio RA2.i dentro del entorno de desarrollo real.

    2.1 Anatomía de un archivo .stories.js

    // Button.stories.js
import { Button } from './Button';

export default {
  title: 'Atoms/Button',
  component: Button,
  argTypes: {
    variant: {
      control: 'select',
      options: ['primary', 'secondary', 'disabled'],
    },
  },
};

export const Primary = {
  args: { variant: 'primary', label: 'Añadir al carrito' },
};

export const Secondary = {
  args: { variant: 'secondary', label: 'Cancelar' },
};

export const Disabled = {
  args: { variant: 'disabled', label: 'No disponible', disabled: true },
};
    Elemento de la Story Función
    title Ruta jerárquica en el menú de navegación de Storybook (Atoms/Button)
    component Componente base documentado e inspeccionado
    argTypes Define los controles interactivos para manipular el estado (RA4.c)
    export const ... Cada exportación individual define un estado/variante concreto ("Story")

    Paralelismo con el Design System de Figma

    Las opciones de argTypes.variant.options (primary, secondary, disabled) representan las mismas variantes que se diseñaron previamente en Figma (UD2). Storybook traduce esas definiciones de diseño a controles ejecutables en código.

    3. Flujo de trabajo con Storybook 

    sequenceDiagram
    participant D as Desarrollador/a
    participant S as Storybook (local)
    participant C as Componente
    participant Doc as Documentación generada

    D->>C: Escribe el componente (HTML/CSS/JS)
    D->>S: Crea el archivo .stories.js
    S->>C: Renderiza el componente aislado
    S->>Doc: Genera automáticamente la documentación (props, variantes)
    D->>S: Ajusta controles interactivos (argTypes)
    S-->>D: Feedback visual inmediato sin recargar la app completa

    # Ejecución del entorno local en http://localhost:6006
npm run storybook

    4. Documentar contenido multimedia dentro de componentes (RA3.d-g) :material-file-media-outline:

    Storybook sirve como catálogo para verificar el tratamiento correcto de los recursos multimedia optimizados en la UD6:

    // Avatar.stories.js — demuestra RA3.d (tratamiento de imagen)
export const ConImagenOptimizada = {
  args: {
    src: 'avatar-usuario.webp', // Formato optimizado trabajado en UD6
    fallback: 'avatar-usuario.jpg',
    alt: 'Foto de perfil de la usuaria',
  },
};

// AudioPlayer.stories.js — demuestra RA3.e (audio/vídeo)
export const ReproductorPodcast = {
  args: {
    src: 'episodio-01.opus',
    fallbackSrc: 'episodio-01.mp3',
    preload: 'none',
  },
};

// LoadingSpinner.stories.js — demuestra RA3.f (animación desde imagen fija)
export const SpinnerAnimado = {
  args: { variant: 'spinner-sprite' }, // Sprite sheet optimizado en UD6 §5
};
    Criterio evaluado Demostración práctica en Storybook
    RA3.d (Tratamiento de imagen) Story que valida componentes con formato moderno WebP y fallback.
    RA3.e (Audio / Vídeo) Story de un reproductor interactivo con atributos de optimización como preload.
    RA3.f (Animación) Story que expone micro-animaciones CSS o sprites importados de la UD6.
    RA3.g (Import / Export de formatos) Integración de assets multimedia optimizados dentro del flujo de desarrollo.

    5. Análisis del código generado (RA4.d)

    Storybook utiliza técnicas de introspección e inspección sintáctica para generar la documentación de propiedades y eventos. El objetivo del criterio RA4.d es analizar críticamente la precisión del código y metadatos generados:

    Addon oficial Documentación generada automáticamente Control y revisión manual necesaria
    @storybook/addon-docs Tablas de props y argTypes con tipos inferidos. Verificar la corrección de los tipos deducidos por el motor.
    @storybook/addon-a11y Reportes automáticos de accesibilidad sobre el DOM generado. Revisión previa antes de abordar las auditorías formales (UD9-UD10 / RA5).
    @storybook/addon-interactions Registro de eventos simulados e interacciones. Comprobar que los casos límites (edge cases) se encuentren cubiertos. 
    flowchart TD
    A["Código del componente"] --> B["Storybook + addon-docs"]
    B --> C["Documentación autogenerada"]
    C --> D{"¿Existe revisión<br/>humana del código?"}
    D -->|No| E["Riesgo de errores en tipos,<br/>props y documentación obsoleta"]
    D -->|Sí| F["Documentación precisa y técnica<br/>(Criterio RA4.d cumplido)"]

    Supervisión del código autogenerado

    La generación automática de documentación no sustituye la verificación por parte del equipo de desarrollo. Un argType mal interpretado (por ejemplo, una propiedad booleana leída como cadena de texto) debe identificarse y corregirse en el archivo .stories.js.

    6. Ejercicio práctico guiado

    Actividad de consolidación (no evaluable)

    Objetivo: Documentar en Storybook los componentes diseñados previamente, cerrando la evaluación práctica de los criterios RA3.d-h.

    Pasos recomendados para practicar:

    1. Instalación: Inicializa Storybook en el proyecto y genera las historias básicas para al menos 3 átomos (Button, Input, Icon).
    2. Integración Multimedia: Crea la historia para un organismo (ProductCard) que combine imágenes optimizadas (RA3.d), un icono SVG (RA3.h) y elementos con micro-animación CSS (RA3.f).
    3. Controles Interactivos: Configura propiedades argTypes personalizadas en al menos 2 componentes (RA4.c).
    4. Inspección A11y: Añade @storybook/addon-a11y para revisar las observaciones de accesibilidad detectadas en la vista previa.
    5. Validación de Código: Revisa la documentación técnica generada por @storybook/addon-docs y ajusta manualmente cualquier discrepancia de tipos (RA4.d).

    7. Resumen de la unidad UD7

    • Atomic Design aporta el marco conceptual y de organización de archivos, mientras que Storybook provee la herramienta ejecutable para visualizar, probar y documentar cada pieza de forma aislada.
    • En esta unidad se da por completado el bloque práctico asignado al RA3 (criterios a-h) y se asientan los fundamentos del RA4 (criterios a, c, d).
    • La integración de herramientas de inspección de accesibilidad en Storybook sirve de preparación previa para el bloque de Accesibilidad y Auditoría Web (RA5) en las UD9 y UD10.
