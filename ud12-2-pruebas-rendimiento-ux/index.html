    2. Declaración del nivel de conformidad alcanzado (RA5.e)

    La elaboración de una Declaración de Accesibilidad técnica y formal (conforme a los requerimientos normativos del RD 1112/2018) sigue una estructura estándar:

    Sección del documento Contenido técnico requerido
    Nivel declarado Nivel de conformidad alcanzado (A, AA o AAA) según las Pautas WCAG 2.2.
    Alcance del informe Listado explícito de URLs o vistas de la aplicación evaluadas.
    Exenciones / Excepciones Justificación formal de contenidos no conformes (Ej. reproductores de vídeo de terceros).
    Metodología aplicada Herramientas automáticas y procedimientos de inspección manual empleados.
    Fecha de auditoría Fecha de emisión de la declaración y calendario de revisiones periódicas. 
    flowchart TD
    A["Auditoría completa WCAG 2.2"] --> B{"¿Cumple nivel AA en todos los criterios aplicables?"}
    B -->|"Sí (Sin excepciones)"| C["<b>Declaración: Conforme AA</b>"]
    B -->|"Sí (Con exenciones documentadas)"| D["<b>Declaración: Parcialmente conforme AA</b>"]
    B -->|"No (Incidencias bloqueantes)"| E["<b>Declaración: No conforme</b><br/>+ Plan de remediación"]

    Gestión de exenciones en proyectos reales

    La clasificación "Parcialmente conforme" es una situación habitual en entornos de desarrollo cuando existen dependencias de software o servicios externos. Lo fundamental es documentar, justificar y aportar una alternativa accesible para los contenidos afectados.

    3. Verificación mediante herramientas externas (RA5.f)

    El criterio RA5.f exige la validación de la interfaz mediante herramientas de análisis externas e independientes al entorno de desarrollo local:

    Herramienta Externa Aportación técnica sobre la inspección en local
    WAVE Web Service Análisis directo desde servidor público, omitiendo estados de sesión locales.
    Accessibility Insights Motor de auditoría de Microsoft con guías asistidas paso a paso para pruebas manuales.
    W3C Markup Validation Service Garantiza la validez y corrección sintáctica del HTML semántico de base.

    Validación en entorno de despliegue real

    Realizar pruebas exclusivamente en el servidor local de desarrollo (localhost) puede enmascarar problemas provocados por cabeceras HTTP de producción, sistemas de minificación o redes CDN. Por ello, el criterio RA5.f exige ejecutar test externos sobre una URL pública o de staging.

    4. Verificación Cross-Browser y de Tecnologías Asistivas (RA5.g)

    Ampliación de la matriz de compatibilidad trabajada en la Sección 8.2, enfocada en la interacción con tecnologías asistivas:

    Navegador Tecnología Asistiva / Entorno Verificación técnica requerida
    Google Chrome Lector de pantalla ChromeVox / Teclado Anuncio correcto de Landmarks, roles ARIA y foco visible.
    Mozilla Firefox Lector NVDA (Windows) Combinación estándar en auditorías profesionales de accesibilidad.
    Apple Safari Lector VoiceOver (macOS / iOS) Gestión de focos modales y comportamiento en eventos táctiles.
    Cualquiera Modo Alto Contraste del SO Percepción de bordes y controles sin dependencia del CSS original.
    Cualquiera Zoom del navegador al 200% Ausencia de desbordamientos o solapamientos de texto (WCAG 1.4.10).

    6. Ejercicio práctico: Proyecto Integrador

    Entregable obligatorio de evaluación

    Objetivo: Elaborar y presentar la memoria de auditoría técnica que consolide la interfaz del proyecto desarrollado durante el curso.

    Requisitos del entregable:

    1. Redacción de la memoria: Completa el documento siguiendo la estructura del apartado 5.
    2. Auditoría externa (RA5.f): Ejecuta un análisis mediante WAVE Web o Accessibility Insights sobre la URL pública de la aplicación (ej. GitHub Pages).
    3. Pruebas asistivas (RA5.g): Documenta el comportamiento de la interfaz al interactuar con al menos un lector de pantalla real (NVDA, VoiceOver o ChromeVox).
    4. Declaración formal (RA5.e): Incluye la Declaración de Conformidad argumentando el nivel alcanzado y las exenciones existentes.
    5. Plan de trabajo: Finaliza el informe estableciendo la matriz de priorización para las correcciones pendientes.
