    12.1 · Métricas de Rendimiento (LCP, INP, CLS) y Optimización

    Nota curricular e impacto

    Ampliación curricular

    Este contenido constituye una ampliación curricular respaldada por el objetivo general k) del título ("Evaluar la interactividad, accesibilidad y usabilidad de una interfaz"). Las técnicas aquí desarrolladas se integran directamente en la auditoría final de la Sección 12.2, la cual cierra formalmente los criterios RA5.e, RA5.f y RA5.g.

    1. Core Web Vitals: concepto y umbrales

    Google introdujo el conjunto de métricas Core Web Vitals para cuantificar la experiencia de usuario real a partir de tres pilares fundamentales: velocidad de carga, capacidad de respuesta y estabilidad visual.

    flowchart TD
    CWV["<b>Core Web Vitals</b>"] --> LCP["<b>LCP</b><br/>Largest Contentful Paint<br/><i>(Velocidad de carga)</i>"]
    CWV --> INP["<b>INP</b><br/>Interaction to Next Paint<br/><i>(Capacidad de respuesta)</i>"]
    CWV --> CLS["<b>CLS</b><br/>Cumulative Layout Shift<br/><i>(Estabilidad visual)</i>"]
    Métrica Dimensión evaluada Umbral Óptimo Nivel de Mejora Deficiente
    LCP Tiempo hasta el renderizado del elemento visual principal (imagen hero, título H1). \(\le \text{2.5 s}\) \(\le \text{4.0 s}\) \(> \text{4.0 s}\)
    INP Latencia entre la interacción del usuario (clic, pulsación) y la actualización del frame visual. \(\le \text{200 ms}\) \(\le \text{500 ms}\) \(> \text{500 ms}\)
    CLS Desplazamiento inesperado del contenido visual durante la fase de carga del documento. \(\le \text{0.1}\) \(\le \text{0.25}\) \(> \text{0.25}\)

    Evolución histórica de las métricas

    En marzo de 2024, la métrica INP (Interaction to Next Paint) reemplazó oficialmente a FID (First Input Delay). A diferencia de FID, que solo evaluaba la primera interacción, INP mide la latencia de todas las interacciones realizadas a lo largo de la sesión del usuario.

    2. LCP (Largest Contentful Paint): causas y optimización 

    flowchart TD
    A["<b>LCP Elevado</b>"] --> B["Respuesta lenta del servidor"]
    A --> C["Bloqueo de renderizado por CSS / JS"]
    A --> D["Recurso LCP no optimizado"]
    A --> E["Renderizado exclusivo en cliente (CSR)"]

    B --> S1["Uso de CDN y estrategias de caché"]
    C --> S2["Inlining de CSS crítico y atributos defer / async"]
    D --> S3["Formatos de imagen modernos (AVIF/WebP) y srcset"]
    E --> S4["Implementación de Server-Side Rendering (SSR)"]
    Causa raíz Solución recomendada Unidad de referencia
    Imagen principal no optimizada Formatos gráficos de nueva generación (AVIF, WebP) y atributo srcset. UD6
    Bloqueo de renderizado por hojas de estilo CSS crítico incrustado e importación asíncrona de fuentes. UD1
    Carga diferida en recursos críticos Evitar la propiedad loading="lazy" en la imagen que actúa como LCP. UD6 
    /* Optimización de carga de tipografías para evitar bloqueo de renderizado */
@font-face {
  font-family: 'Inter';
  src: url('inter-var.woff2') format('woff2');
  font-display: swap; /* Utiliza la tipografía del sistema mientras descarga el recurso */
}

    3. INP (Interaction to Next Paint): gestión del hilo principal 

    flowchart LR
    A["Interacción del usuario"] --> B["Script extenso bloquea el hilo principal"]
    B --> C["Retraso en el renderizado del siguiente frame"]
    C --> D["Fricción percibida / Interfaz bloqueada"]
    Técnica de optimización Impacto en la latencia
    Fragmentación de tareas (requestIdleCallback / setTimeout) Divide ejecuciones extensas en micro-tareas evitando el bloqueo prolongado del hilo principal.
    Debounce y Throttle Limita la frecuencia de ejecución en eventos continuos (input, scroll, resize).
    Delegación de eventos Reduce el volumen de escuchadores registrados en el DOM HTML (UD8). 
    // Implementación de función Debounce para optimizar búsquedas interactivas
function debounce(fn, delay) {
  let timeoutId;
  return (...args) => {
    clearTimeout(timeoutId);
    timeoutId = setTimeout(() => fn(...args), delay);
  };
}

const aplicarFiltro = debounce((query) => {
  console.log('Procesando búsqueda:', query);
}, 300);

document.querySelector('#campo-busqueda').addEventListener('input', (e) => {
  aplicarFiltro(e.target.value);
});

    4. CLS (Cumulative Layout Shift): estabilidad de maquetación 

    flowchart TD
    A["<b>CLS Inestable</b>"] --> B["Imágenes y elementos multimedia sin dimensiones"]
    A --> C["Inyección dinámica de elementos en zonas superiores"]
    A --> D["Carga asíncrona de tipografías sin reserva de espacio"]

    Marcado HTML y CSS para prevenir desplazamientos

    <!-- Incorrecto: El navegador no reserva el espacio y desplaza el contenido tras la descarga -->
<img src="producto.webp" alt="Zapatillas deportivas">

<!-- Correcto: Definición implícita de relación de aspecto -->
<img src="producto.webp" alt="Zapatillas deportivas" width="400" height="300">

    /* Estrategia en CSS mediante reserva de espacio de aspecto */
.card__media {
  width: 100%;
  aspect-ratio: 4 / 3;
  background-color: var(--color-placeholder);
}
    Buena práctica de maquetación Justificación técnica
    Explicitar width y height en etiquetas de imagen Permite al navegador calcular el espacio en el Layout antes de descargar el archivo.
    Espacios reservados (placeholders / skeletons) Previene saltos visuales durante la inserción de anuncios o componentes dinámicos.
    Utilizar transform para animaciones CSS Evita activar las fases de Layout y Reflow en el motor de renderizado.

    5. Herramientas de diagnóstico de rendimiento

    Herramienta Entorno de medición Caso de uso principal
    Lighthouse Datos de laboratorio (Simulados). Evaluación rápida en fases de desarrollo local (UD10).
    PageSpeed Insights Laboratorio + Datos de campo reales (CrUX). Análisis de experiencia real acumulada de usuarios finales.
    Chrome DevTools (Performance) Datos de laboratorio profundos. Perfilado exhaustivo del hilo principal y trazas de JavaScript. 
    flowchart LR
    A["<b>Datos de Laboratorio</b><br/>(Pruebas sintéticas en entornos controlados)"] --> C["<b>Diagnóstico Integral</b>"]
    B["<b>Datos de Campo</b><br/>(Métricas reales extraídas de usuarios / CrUX)"] --> C

    Diferenciación de entornos de prueba

    Los datos de laboratorio son ideales para detectar regresiones durante el desarrollo. Sin embargo, las métricas de campo extraídas del informe CrUX representan la validación definitiva del rendimiento percibido en dispositivos y redes reales.

    6. Ejercicio práctico guiado

    Actividad de consolidación (no evaluable)

    Objetivo: Auditar, corregir y documentar el rendimiento técnico de la aplicación web desarrollada.

    Pasos recomendados para practicar:

    1. Medición inicial: Ejecuta un informe de Lighthouse (categoría Performance) y registra las métricas de LCP, TBT (proxy de INP en laboratorio) y CLS.
    2. Optimización LCP: Identifica la imagen o nodo principal del LCP y aplica optimizaciones de formato (WebP/AVIF) y prioridad de carga.
    3. Estabilidad CLS: Asegura la inclusión de atributos width y height o la propiedad aspect-ratio en todas las imágenes del proyecto.
    4. Medición final: Re-ejecuta el análisis de rendimiento y elabora una tabla comparativa con las métricas obtenidas antes y después del ajuste.
