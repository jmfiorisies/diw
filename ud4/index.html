    1. Formas de aplicar CSS (RA2.b, RA2.c)

    Método Sintaxis Cuándo usarlo
    En línea (inline) <p style="color: red;"> Casi nunca en producción — máxima especificidad, muy difícil de mantener
    Interno <style> dentro del <head> Prototipos rápidos o componentes aislados en algunos entornos
    Externo <link rel="stylesheet" href="styles.css"> El estándar en proyectos reales — cacheable, reutilizable y escalable

    2.1 Orden de la cascada

    flowchart TD

    2.2 Cálculo de especificidad

    Tipo de selector Peso Ejemplo
    Estilo en línea 1000 style="color: red"
    ID 100 #header
    Clase, atributo, pseudo-clase 10 .btn, [type="submit"], :hover
    Elemento, pseudo-elemento 1 div, ::before
    Selector Cálculo Especificidad total
    div 1 (0, 0, 0, 1)
    .btn 10 (0, 0, 1, 0)
    #nav .btn 100 + 10 (0, 1, 1, 0)
    div#nav .btn:hover 1 + 100 + 10 + 10 (0, 1, 2, 1)

    Cuidado con el abuso de !important

    Abusar de !important para ganar a la especificidad es una deuda técnica importante, no una solución. Cada !important añadido obliga al equipo a usar otro más fuerte en el futuro. La arquitectura correcta de CSS (metodología BEM, que veremos en la UD5) se utiliza para no necesitar nunca !important.

    2.3 Herencia

    Propiedades que SÍ heredan por defecto Propiedades que NO heredan por defecto
    color, font-family, font-size, line-height margin, padding, border, width, height
    text-align, visibility background, display, position

    3. El modelo de caja (Box Model) 

    flowchart TD
    subgraph BoxModel ["Caja CSS (Modelo de Caja)"]
        M["<b>Margin</b> (Espacio externo)"] --> B["<b>Border</b> (Borde del contenedor)"]
        B --> P["<b>Padding</b> (Espaciado interno)"]
        P --> C["<b>Content</b> (Área de contenido)"]
    end
    Propiedad box-sizing Qué incluye width / height
    content-box (Por defecto) Solo el contenido — padding y border se suman aparte alterando el tamaño final
    border-box (Recomendado) Contenido + padding + border, todo encajado dentro del valor declarado

    Resets globales recomendados

    La práctica recomendada en el desarrollo web moderno es aplicar *, *::before, *::after { box-sizing: border-box; } al inicio de la hoja de estilos. Esto evita discrepancias de tamaño al añadir padding o bordes a los elementos.

    4. Flexbox: layout en una dimensión 

    flowchart TD
    subgraph FlexContainer ["Contenedor Flex (flex-direction: row)"]
        I1["Item 1"] --> I2["Item 2"] --> I3["Item 3"]
    end
    Propiedad (en el contenedor) Efecto
    display: flex Activa el comportamiento Flexbox en los hijos directos
    flex-direction Define el eje principal: row
    justify-content Alineación de elementos a lo largo del eje principal
    align-items Alineación de elementos a lo largo del eje secundario
    gap Espaciado entre elementos sin recurrir a márgenes manuales
    flex-wrap Permite que los elementos salten de línea si no caben
    Propiedad (en los elementos hijos) Efecto
    flex-grow Proporción de crecimiento del elemento respecto a los demás
    flex-shrink Capacidad de encogimiento cuando falta espacio en el contenedor
    flex-basis Tamaño de partida antes de repartir el espacio disponible

    Relación con Figma

    Tal como vimos en la UD2, la combinación flex-direction: row + gap + padding en CSS equivale exactamente al Auto Layout horizontal de Figma.

        direction LR

            A1["Celda 1,1"] --- A2["Celda 1,2"] --- A3["Celda 1,3"]

        subgraph Fila2 ["Fila 2"]
            B1["Celda 2,1"] --- B2["Celda 2,2"] --- B3["Celda 2,3"]

    Propiedad Efecto
    display: grid Activa el motor CSS Grid en los hijos directos
    grid-template-columns Define número y proporción de columnas (1fr 1fr 1fr, repeat(3, 1fr))
    grid-template-rows Define número y tamaño de filas
    gap Espaciado interno entre celdas (filas y columnas)
    grid-column / grid-row Permite expandir un elemento a lo largo de varias celdas
    grid-template-areas Maquetación visual mediante nombres de áreas ("header header" "sidebar main")

    5.1 ¿Flexbox o Grid?

    Necesidad de maquetación Herramienta recomendada
    Alinear elementos en una sola fila o columna Flexbox
    Definir el layout general de la página (header, sidebar, main, footer) CSS Grid
    Que el contenido dicte el tamaño dinámico de los elementos Flexbox
    Que una rejilla fija controle la posición de cada bloque CSS Grid
    Estructuras complejas de aplicación web Ambos (Grid para la estructura general, Flexbox en el interior de cada componente)

    Q{"¿Necesito controlar<br/>filas Y columnas a la vez?"}

    6. Responsive design y Container Queries

    6.1 Media Queries (Por Viewport)

    /* Estrategia Mobile-First: estilos base para móviles, ampliados hacia arriba */
.card { 
  grid-template-columns: 1fr; 
}

@media (min-width: 768px) {
  .card { 
    grid-template-columns: repeat(2, 1fr); 
  }
}

@media (min-width: 1200px) {
  .card { 
    grid-template-columns: repeat(3, 1fr); 
  }
}
    Enfoque Ventaja técnica
    Mobile-First (min-width) El código base es más ligero y añade complejidad conforme crece la pantalla
    Desktop-First (max-width) Práctico al refactorizar o mantener proyectos heredados diseñados para escritorio

    6.2 Container Queries (Receptividad por Contenedor)

    Las Media Queries reaccionan al ancho de la pantalla global (viewport). Las Container Queries reaccionan al ancho del propio contenedor padre, permitiendo crear componentes verdaderamente modulares que cambian su aspecto según la zona donde se ubiquen.

    .card-container {
  container-type: inline-size;
  container-name: card;
}

@container card (min-width: 400px) {
  .card { 
    grid-template-columns: 1fr 2fr; 
  }
}

    flowchart TD
    MQ["<b>Media Query</b><br/>Reacciona al tamaño total del viewport"] -->|Limitación| L["No permite adaptar un componente según la columna donde esté ubicado"]
    CQ["<b>Container Query</b><br/>Reacciona al tamaño de su contenedor directo"] --> S["El componente se adapta autónomamente según el espacio disponible"]

    6.3 Hojas de estilo alternativas (RA2.d)

    Evolución de las hojas de estilo alternativas hacia el uso moderno de custom properties y preferencias del sistema:

    :root {
  --bg-color: #ffffff;
  --text-color: #1a1a1a;
}

@media (prefers-color-scheme: dark) {
  :root {
    --bg-color: #121212;
    --text-color: #f0f0f0;
  }
}

body {
  background: var(--bg-color);
  color: var(--text-color);
}
    Enfoque histórico Solución actual equivalente Objetivo
    <link rel="alternate stylesheet"> mediante JS prefers-color-scheme + CSS Custom Properties Ofrecer un esquema de color alternativo (Modo Oscuro/Claro) nativo
    Hoja de impresión (media="print") Regla @media print Aplicar estilos específicos al imprimir el documento

    7. Ejercicio práctico guiado

    Actividad de consolidación (no evaluable)

    Objetivo: Maquetar mediante CSS3 moderno la estructura semántica construida en la unidad anterior (UD3).

    Pasos recomendados para practicar:

    1. Reset Inicial: Aplica box-sizing: border-box de forma universal en tu hoja de estilos.
    2. Estructura General: Implementa el layout principal de la página usando CSS Grid (grid-template-areas) asociando <header>, <main> y <footer>.
    3. Componentes: Maqueta las tarjetas de producto interiores usando Flexbox para alinear sus elementos (imagen, título, descripción, precio y botón).
    4. Diseño Adaptable: Configura al menos 2 puntos de ruptura (breakpoints) siguiendo la metodología Mobile-First.
    5. Tema Oscuro: Añade variables CSS y la regla @media (prefers-color-scheme: dark) para dar soporte a modo oscuro.
    6. Container Queries (Avanzado): Transforma la tarjeta de producto para que use @container en lugar de una media query global.

    8. Resumen y conexión con la siguiente unidad

    • La cascada sigue un orden estricto: origen \(\rightarrow\) especificidad \(\rightarrow\) orden de aparición.
    • Flexbox administra un eje unidimensional; CSS Grid administra dos ejes a la vez. Se complementan en producción.
    • Las Container Queries permiten que los componentes sean 100% independientes del viewport.
    • En la UD5 estructuraremos estos estilos aplicando arquitecturas escalables como la metodología BEM y frameworks Utility-First como Tailwind CSS.
