    1. Derechos de autor y licencias (RA3.a)

    Tipo de licencia Qué permite Ejemplo de uso
    Copyright estándar (©) Reservados todos los derechos. Sin permiso explícito no se puede reutilizar. Fotografías de stock de pago o bancos privados.
    Creative Commons — CC BY Uso libre, modificación y distribución citando expresamente al autor. Iconografía, fotografías de bancos de recursos abiertos.
    CC BY-SA Igual que CC BY + obras derivadas deben distribuirse bajo la misma licencia. Wikipedia y proyectos colaborativos.
    CC BY-NC Uso libre salvo para fines comerciales o con ánimo de lucro. Recurso de fines educativos o de investigación.
    CC0 / Dominio público Libre uso sin restricciones ni obligación de atribución. Unsplash, Pexels, Pixabay.
    SIL Open Font License (OFL) Específica para tipografías. Permite uso, modificación y redistribución. Google Fonts.

    Uso indebido de motores de búsqueda

    Encontrar un archivo mediante un buscador de imágenes no equivale a tener permiso legal para su uso. El origen del recurso define las condiciones de uso real.

    2. Formatos de imagen (RA3.b, RA3.c, RA3.d)

    2.1 Imágenes rasterizadas vs. vectoriales

    Tipo Cómo se almacena Comportamiento al escalar Formatos típicos
    Raster (Mapa de bits) Rejilla fija de píxeles con valor de color Se pixela al aumentar su tamaño original JPEG, PNG, WebP, AVIF
    Vectorial Fórmulas matemáticas (puntos, vectores, curvas) Escala infinita sin pérdida de definición SVG

    2.2 Comparativa de formatos rasterizados

    Formato Compresión Transparencia Compatibilidad Cuándo utilizarlo
    JPEG Con pérdida No Universal Fotografías y complejas sin necesidad de canal alfa.
    PNG Sin pérdida Sí Universal Capturas, ilustraciones o imágenes que exijan transparencia nítida.
    WebP Con/sin pérdida Sí > 96% navegadores Sustituto estándar para JPEG/PNG. 25-35% más ligero.
    AVIF Con/sin pérdida Sí Creciente Máxima eficiencia de compresión actual. Ideal para imágenes pesadas. 
    flowchart TD
    A{"¿Es un icono, logo o gráfico<br/>con formas geométricas?"}
    A -->|Sí| SVG["<b>Formato SVG</b><br/>(Vectorial escalable)"]
    A -->|No, es una fotografía| B{"¿Requiere canal<br/>de transparencia?"}
    B -->|Sí| C{"¿Prioridad del proyecto?"}
    B -->|No| C
    C -->|Máxima compresión| AVIF["<b>AVIF</b><br/>(Formato de última generación)"]
    C -->|Compatibilidad global| WEBP["<b>WebP</b><br/>(Con fallback a JPEG/PNG)"]

    2.3 Selección de formatos mediante <picture>

    <picture>
  <source srcset="producto.avif" type="image/avif">
  <source srcset="producto.webp" type="image/webp">
  <img src="producto.jpg" alt="Zapatillas running" loading="lazy">
</picture>

    El navegador procesa en orden descendente y selecciona el primer formato compatible, manteniendo JPEG como red de seguridad universal.

    2.4 Responsive images con srcset y sizes

    <img
  src="producto-800.jpg"
  srcset="producto-400.jpg 400w, producto-800.jpg 800w, producto-1200.jpg 1200w"
  sizes="(max-width: 600px) 100vw, 50vw"
  alt="Zapatillas running"
  loading="lazy">
    Atributo Función
    srcset Ofrece diferentes resoluciones del recurso junto a su ancho real expresado en w.
    sizes Indica al motor del navegador qué porcentaje del viewport ocupará la imagen.
    loading="lazy" Retrasa la petición hasta que el elemento se aproxima al viewport visible.

    2.5 Gráficos vectoriales (SVG)

    <svg viewBox="0 0 24 24" width="24" height="24" fill="currentColor">
  <path d="M12 2L2 7l10 5 10-5-10-5z"/>
</svg>
    Ventaja del uso de SVG Inline Motivo técnico
    Estilización mediante CSS Permite usar fill: currentColor para adoptar el color del texto contenedor (útil en temas claro/oscuro).
    Manipulación del DOM Cada nodo o trazado (<path>) se puede animar individualmente con CSS/JS.
    Reducción de peticiones HTTP Al integrarse directo en el HTML, evita una solicitud de red adicional.

    4. Audio y vídeo en la web (RA3.e) :material-video-film:

    4.1 Formatos de audio

    Formato Compresión Compatibilidad Ámbito de uso
    MP3 Con pérdida Universal Estándar histórico para compatibilidad universal.
    AAC Con pérdida Muy alta Ajustado para streaming y plataformas multimedia.
    Opus Con pérdida Alta (Navegadores modernos) Máxima eficiencia de compresión en voz y música.

    4.2 Formatos de vídeo

    Formato / Códec Compresión Compatibilidad Ámbito de uso
    MP4 (H.264) Con pérdida Universal Estándar de reproducción global sin fallos de soporte.
    WebM (VP9) Con pérdida Alta Alta eficiencia de compresión para desarrollo web moderno.
    AV1 Con pérdida En expansión Mayor ratio de compresión actual sin pérdida apreciable de calidad.

    4.3 Elementos nativos de HTML5

    <audio controls preload="none">
  <source src="podcast.opus" type="audio/opus">
  <source src="podcast.mp3" type="audio/mpeg">
  Tu navegador no admite el elemento de audio HTML5.
</audio>

<video controls poster="miniatura.jpg" preload="metadata">
  <source src="demo.webm" type="video/webm">
  <source src="demo.mp4" type="video/mp4">
  Tu navegador no admite el elemento de vídeo HTML5.
</video>
    Atributo Función
    controls Habilita la interfaz de reproducción predeterminada del navegador.
    preload="none" / "metadata" Evita la descarga del archivo pesado hasta que el usuario activa la reproducción.
    poster Define una imagen de portada previa a la reproducción del vídeo.

    4.4 Herramientas para la conversión de medios (RA3.g)

    Herramienta Tipo Uso principal
    Audacity Editor de audio libre Recorte, normalización de sonido y conversión entre formatos.
    HandBrake Conversor de vídeo Codificación de vídeo a formatos WebM/MP4 optimizados para web.
    FFmpeg Herramienta CLI Procesamiento por lotes y automatización en scripts. 
    # Ejemplo de conversión de vídeo MP4 a WebM con el códec VP9 usando FFmpeg
ffmpeg -i demo.mp4 -c:v libvpx-vp9 -crf 30 -b:v 0 demo.webm

    5. Animaciones desde imágenes fijas (RA3.f)

    Técnicas habituales para aportar dinamismo a la interfaz sin incurrir en el peso de un archivo de vídeo:

    5.1 Sprite Sheets con CSS

    Consiste en usar una imagen única que agrupa los fotogramas en secuencia y cambiar el background-position con CSS:

    .sprite-animado {
  width: 64px;
  height: 64px;
  background-image: url('sprite-8-frames.png');
  background-size: 800% 100%;
  animation: reproducir 0.8s steps(8) infinite;
}

@keyframes reproducir {
  from { background-position: 0% 0; }
  to   { background-position: 100% 0; }
}

    5.2 CSS @keyframes sobre imágenes vectoriales o fijas

    .logo-flotante {
  animation: flotar 3s ease-in-out infinite;
}

@keyframes flotar {
  0%, 100% { transform: translateY(0); }
  50%      { transform: translateY(-10px); }
}

    5.3 WebP Animado

    Sustituye al formato GIF tradicional ofreciendo transparencia real, colores de 24 bits y mayor tasa de compresión.

    flowchart TD
    A["¿Qué tipo de animación se requiere?"] --> B{"Transformaciones simples<br/>(desplazamiento, rotación, escala)"}
    B -->|Sí| CSS["<b>CSS @keyframes</b><br/>sobre el recurso individual"]
    B -->|No, animación fotograma a fotograma| C{"¿Es un icono o recurso<br/>que se repite en bucle?"}

    6. Introducción a Performance Multimedia

    Optimizar el rendimiento desde la capa multimedia es la primera fase para garantizar métricas óptimas de experiencia de usuario:

    Estrategia de optimización Impacto en rendimiento Implementación
    Carga diferida (loading="lazy") Evita peticiones iniciales innecesarias fuera de la vista. §2.4
    Estrategia preload adecuada Reduce el consumo de datos inicial en elementos de audio/vídeo. §4.3
    Adopción de WebP/AVIF Disminuye el peso transferido sin pérdidas visuales de calidad. §2.2
    **Dimensionamiento con srcset** Sirve recursos escalados a la resolución exacta del dispositivo. §2.4

    7. Ejercicio práctico guiado

    Actividad de consolidación (no evaluable)

    Objetivo: Desarrollar un paquete optimizado de recursos multimedia para la interfaz maquetada en las unidades anteriores.

    Pasos recomendados para practicar:

    1. Licencias: Selecciona 3 recursos fotográficos en bancos con licencia CC0 o CC BY y registra los datos de atribución en un documento.
    2. Compresión: Procesa una imagen con Squoosh para exportarla en JPEG, WebP y AVIF; evalúa las diferencias de peso respecto a la calidad visual.
    3. Implementación Responsive: Elabora un bloque <picture> que combine las versiones exportadas con fallback y carga diferida (loading="lazy").
    4. Limpieza SVG: Exporta un icono desde Figma, optimiza su estructura mediante SVGO e intégralo en el HTML como SVG inline manipulable con CSS.
    5. Elementos Multimedia: Configura un reproductor de audio <audio> y uno de vídeo <video> integrando opciones de formato secundarias y atributos preload optimizados.
    6. Micro-animación: Diseña una animación con CSS @keyframes aplicada sobre un elemento gráfico de la página.

    8. Resumen y conexión con la siguiente unidad

    • Toda elección de recurso multimedia debe responder a criterios de licencia, formato y peso.
    • Los formatos WebP y AVIF son el estándar preferente para mapas de bits, mientras que SVG lidera en iconografía.
    • Los reproductores HTML5 deben ofrecer alternativas de formato mediante múltiples nodos <source>.
    • Con el RA3 explicado conceptualmente, en la UD7 aplicaremos estos recursos multimedia en componentes reutilizables utilizando Storybook.
