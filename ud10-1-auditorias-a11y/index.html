    10.1 · Herramientas Automáticas de Diagnóstico

    Criterios trabajados

    Criterio Cobertura
    RA5.c — Se han identificado las principales pautas de accesibilidad al contenido ✅ Completa
    RA5.f — Se han verificado los niveles alcanzados mediante el uso de test externos 🟡 Parcial (se completa en UD12)

    1. Panorama de herramientas automáticas 

    flowchart TD
    A["Herramientas de auditoría A11y"] --> B["<b>Lighthouse</b><br/>(Integrada en Chrome DevTools)"]
    A --> C["<b>axe DevTools</b><br/>(Extensión basada en axe-core)"]

    Lighthouse Integrada en Chrome DevTools axe-core (parcial) Puntuación 0-100 + listado de auditorías.

    | | axe DevTools | Extensión de navegador | axe-core (Deque Systems) | Lista de incidencias por severidad con enlaces a normas WCAG.

    | | WAVE | Extensión + versión web | Motor propio de WebAIM | Overlay visual directamente sobre la página.

    |

    Complementariedad entre herramientas

    Aunque varias herramientas comparten el mismo motor base (axe-core), los algoritmos de análisis y la presentación de datos varían. Una auditoría profesional no se limita a un solo software; se recomienda combinar varias herramientas para maximizar la cobertura de detección automatizable.

    2. Lighthouse

    2.1 Proceso de ejecución

    sequenceDiagram
    participant U as Usuario/a
    participant DT as Chrome DevTools
    participant L as Motor Lighthouse
    participant R as Informe

    U->>DT: Abre DevTools (F12) → pestaña Lighthouse
    U->>DT: Selecciona categorías (Accessibility, Performance...)
    DT->>L: Ejecuta la auditoría
    L->>R: Genera informe con puntuación y hallazgos
    R-->>U: Lista de auditorías aprobadas/fallidas

    2.2 Categorías de auditoría relevantes

    Categoría Relación con el módulo
    Accessibility RA5 (Objeto de esta unidad).
    Performance RA5.e y UD12 (Core Web Vitals).
    Best Practices Transversal (Buenas prácticas del desarrollo web).
    SEO Requisitos técnicos complementarios (uso de alt, lang, etc.).

    2.3 Interpretación de la puntuación

    Rango Interpretación
    90 - 100 Nivel óptimo de accesibilidad automatizable (no implica accesibilidad total).
    50 - 89 Requiere revisiones y corrección de barreras relevantes.
    0 - 49 Presencia de barreras de accesibilidad graves.

    Límite del análisis automático

    La puntuación de Lighthouse mide únicamente los parámetros automáticos (aproximadamente entre un 30% y 40% de las pautas WCAG). Obtener 100/100 en Lighthouse no certifica el cumplimiento total del Nivel AA; solo confirma la ausencia de errores detectables por código. La prueba manual (10.2) continúa siendo imprescindible.

    3. axe DevTools

    3.1 Estructura de una incidencia detectada por axe

    {
  "id": "color-contrast",
  "impact": "serious",
  "description": "Elements must meet minimum color contrast ratio thresholds",
  "help": "Elements must have sufficient color contrast",
  "helpUrl": "[https://dequeuniversity.com/rules/axe/4.7/color-contrast](https://dequeuniversity.com/rules/axe/4.7/color-contrast)",
  "nodes": [
    { 
      "target": [".card-producto__price"], 
      "html": "<p class=\"card-producto__price\">79,99 €</p>" 
    }
  ]
}
    Campo Función
    impact Clasificación de severidad: minor, moderate, serious, critical.
    nodes Elementos exactos del DOM afectados y sus selectores CSS.
    helpUrl Enlace a la documentación técnica con la regla WCAG asociada.

    3.2 Clasificación del impacto y priorización

    Severidad (impact) Prioridad de solución Ejemplo habitual
    critical Inmediata (Bloquea el uso) Elemento interactivo que no recibe foco por teclado.
    serious Alta Contraste insuficiente o ausencia de alt en imágenes informativas.
    moderate Media Landmarks repetidos sin etiquetado diferenciador (aria-label).
    minor Baja Redundancias menores en lecturas de sintesis de voz.

    4. WAVE (Web Accessibility Evaluation Tool)

    4.1 Enfoque visual e inspección sobre la interfaz

    A diferencia de los informes en formato de lista, WAVE superpone indicadores visuales directamente sobre la página renderizada.

    flowchart TD
    A["Página renderizada"] --> B["WAVE superpone indicadores:<br/>❌ Error · ⚠️ Alerta · ℹ️ Característica"]
    B --> C["Selección del icono:<br/>Muestra explicación y código fuente afectado"]
    Indicador Significado
    Error (Rojo) Incidencia confirmada de accesibilidad (ej. imagen sin atributo alt).
    Alerta (Amarillo) Elemento que requiere inspección manual (ej. enlaces con texto "Leer más").
    Característica (Verde) Semántica o técnica accesible correctamente implementada.
    Contraste Señala los elementos de texto con relación de contraste deficiente.

    Presentación de resultados

    WAVE resulta especialmente útil para presentar diagnósticos a perfiles no técnicos (equipos de diseño o cliente), ya que permite visualizar la localización de las barreras directamente sobre el diseño.

    5. Alcance y limitaciones del análisis automático

    Comparativa entre verificación automatizada e inspección humana:

    Requisito o Pauta WCAG ¿Automatizable? Justificación técnica
    ¿El texto alt describe adecuadamente la imagen? ❌ No El software valida la existencia del atributo, no el sentido del texto.
    ¿El orden de navegación por teclado es intuitivo? ⚠️ Parcial Detecta valores erróneos de tabindex, pero no la coherencia del flujo.
    ¿Los mensajes de error en formularios son claros? ❌ No Evalúa la presencia de etiquetas, no la claridad de la redacción.
    ¿El componente es comprensible con lector de pantalla? ❌ No Requiere verificación humana práctica (UD9.2).
    Contraste de color entre texto y fondo ✅ Sí Es una fórmula matemática determinista.
    Presencia de etiquetas de estructura (alt, lang) ✅ Sí Es una comprobación de sintaxis en el DOM. 
    flowchart TD
    A["Criterios de conformidad WCAG"] --> B["<b>~30-40%</b><br/>Automatizable<br/>(Lighthouse, axe, WAVE)"]
    A --> C["<b>~60-70%</b><br/>Revisión humana obligatoria<br/>(Teclado, lector de pantalla, criterio experto)"]

    6. Ejercicio práctico guiado

    Actividad de consolidación (no evaluable)

    Objetivo: Ejecutar las tres herramientas automáticas sobre el proyecto e interpretar las coincidencias y discrepancias en los informes.

    Pasos recomendados para practicar:

    1. Auditoría con Lighthouse: Lanza la prueba en Chrome DevTools (categoría Accessibility) y registra la puntuación junto con los errores principales.
    2. Análisis con axe DevTools: Ejecuta el panel de axe sobre la misma vista y clasifica los fallos según su severidad (critical, serious, moderate, minor).
    3. Inspección visual con WAVE: Activa la extensión WAVE y toma una captura de la interfaz con los indicadores superpuestos.
    4. Comparativa de resultados: Elabora una tabla unificada con los hallazgos para preparar el plan de corrección priorizado que se abordará en la Sección 10.2.
